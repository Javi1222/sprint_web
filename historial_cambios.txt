1. ARQUITECTURA DEL SISTEMA EN 3 CAPAS
--------------------------------------------------------------------------------
La aplicación sigue el modelo clásico cliente-servidor desacoplado en tres capas:

  A) CAPA DE PRESENTACIÓN / FRONTEND (index.html + CSS + Vanilla JS):
     - Se ejecuta directamente en el navegador web del usuario.
     - Captura los datos ingresados en los formularios mediante el DOM.
     - Utiliza la API nativa 'fetch()' de forma asíncrona (async/await) para enviar
       y recibir información en formato JSON hacia el backend sin recargar la página.

  B) CAPA LÓGICA / BACKEND (Node.js + Express en puerto 3000):
     - Servidor HTTP intermediario construido en Node.js con Express (server.js).
     - Habilita 'cors()' para permitir peticiones cruzadas desde el navegador.
     - Interpreta el cuerpo de las peticiones mediante el middleware 'express.json()'.
     - Aplica validaciones de seguridad (expresiones regulares y listas blancas).
     - Gestiona la conexión persistente con MySQL y ejecuta las sentencias SQL.

  C) CAPA DE DATOS (MySQL Server 8.0 en puerto 3306):
     - Motor relacional de base de datos que garantiza almacenamiento persistente,
       atomicidad e integridad de la información en disco duro.
     - Base de datos utilizada: 'sprint_web'.


2. FLUJO COMPLETO DE LOS DOS CASOS DE USO DE LA APLICACIÓN
--------------------------------------------------------------------------------

CASO DE USO 1: REGISTRO DE UN NUEVO USUARIO
-------------------------------------------
1. El usuario introduce su nombre y apellidos en el formulario 1 y pulsa "Enviar a MySQL".
2. La función JavaScript 'enviarDatos()' (Frontend) valida que los campos no estén vacíos.
3. Se serializan los datos en formato JSON: { "nombre": "...", "apellidos": "..." }.
4. 'fetch()' lanza una petición asíncrona HTTP POST a 'http://localhost:3000/api/usuarios'.
5. El servidor Express (Backend) intercepta la petición en la ruta '/api/usuarios'.
6. 'express.json()' parsea el JSON y extrae 'nombre' y 'apellidos' de 'req.body'.
7. Se ejecuta la consulta parametrizada:
      INSERT INTO usuarios (nombre, apellidos) VALUES (?, ?)
   (El uso de '?' delega en el driver mysql2 el escape de caracteres, blindando la app
   contra inyecciones SQL en valores literales).
8. MySQL guarda físicamente el registro asignando un 'id' autoincremental único.
9. El backend recibe el acuse de recibo de MySQL y responde al frontend con HTTP 200/201.
10. El frontend recibe la confirmación ('respuesta.ok'), muestra una alerta de éxito
    y vacía los campos del formulario.

CASO DE USO 2: CREACIÓN DINÁMICA DE TABLAS EN MYSQL
---------------------------------------------------
1. El usuario ingresa el nombre de la tabla que desea crear (ej: 'productos') y define
   sus columnas adicionales (nombre y tipo de dato: VARCHAR, INT, DECIMAL, etc.).
2. La interfaz permite añadir o retirar filas de columnas de manera 100% interactiva.
3. Al pulsar "Crear Tabla en MySQL", la función 'crearTablaMySQL()' valida en el cliente
   los identificadores mediante expresiones regulares (/^[a-zA-Z0-9_]+$/).
4. Se envía un objeto JSON estructurado mediante POST a 'http://localhost:3000/api/tablas':
   {
      "nombreTabla": "productos",
      "columnas": [ { "nombre": "precio", "tipo": "DECIMAL(10,2)" } ]
   }
5. El backend realiza una doble capa de seguridad crítica:
   * En SQL, los nombres de tablas y columnas (identificadores) NO admiten parámetros '?'.
   * Por ello, el servidor valida el nombre con regex y contrasta cada tipo contra una
     lista blanca permitida (VARCHAR, INT, TEXT, DATE, etc.).
6. Se construye de forma segura la sentencia DDL:
      CREATE TABLE IF NOT EXISTS `nombreTabla` (`id` INT AUTO_INCREMENT PRIMARY KEY, ...)
7. El driver 'mysql2' despacha la sentencia mediante protocolo TCP hacia MySQL.
8. La tabla queda creada físicamente en el esquema 'sprint_web' de MySQL.
9. El backend devuelve un estado HTTP 201 confirmando la creación y el frontend muestra
   un mensaje de éxito en pantalla.


3. PROTOCOLOS Y COMUNICACIÓN ENTRE CAPAS
--------------------------------------------------------------------------------

             |
             |  Petición HTTP (POST) / Formato JSON
             v
   [ 2. BACKEND: Express (Puerto 3000) ]
             |
             |  Protocolo binario TCP / Driver mysql2 / Puerto 3306
             v
   [ 3. BASE DE DATOS: MySQL 8.0 (Puerto 3306) ]
